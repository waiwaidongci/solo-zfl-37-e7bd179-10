# 墨锭试磨室

运行：

```bash
npm start
```

访问 `http://localhost:3037`。数据保存在 `data/ink-stick-testing.json`。

## 原料风险追溯台

入口：页面右上角「进入原料风险追溯台 →」，或直接访问 `http://localhost:3037/risk`。

能力：

- **批次 / 留样 / 试磨绑定**：每次试磨绑定原料批次与留样编号，同一留样全局只能使用一次（含并发抢占，仅一次成功）。
- **原料异常预警**：提交预警后系统沿「批次 → 留样 → 试磨记录 → 墨锭」关系计算影响范围并一次性冻结；冻结对象禁止再写入（新增留样、改状态、备注、试磨均被拦截）。
- **预警生命周期**：待确认 → 已确认 → 处理中 →（放行/召回）→ 待复核 → 已复核 → 已关闭。非法跳转、回退、重复提交一律拒绝。**待复核必须先复核**：未复核直接关闭返回 `409 review_required`，预警状态、时间线、审计、冻结均不变化；只有进入“已复核”后才能关闭（召回还需复测全部完成）。
- **职责分离（提交人回避）**：预警提交人既不能审核放行/召回，也不能在待复核阶段自行复核——`release`/`recall`/`review` 由提交人执行均返回 403，且状态、时间线、审计、冻结均不变化；复核须由其他操作人完成。
- **审核只能放行或召回**：召回复核前保留原试磨结论快照，并为每条受影响试磨生成复测任务；复测全部完成前召回预警不能关闭。
- **页面**：显示风险等级、影响数量、冻结原因，支持桌面与手机（响应式）。
- **旧入口与旧数据保留**：`/` 旧页面、`/api/items` 系列接口、旧墨锭与试磨数据不变；旧数据在首次启动时自动补结构迁移。

### 持久化与一致性

- 所有写入经单一写队列串行化，在锁内重读最新数据，避免读后写竞争。
- 写盘采用「临时文件 + 原子 rename」，配合单调递增 `revision`：写失败时预警、影响范围、冻结、审计不会部分落盘。
- `GET /api/consistency` 返回关系/版本自检结果（留样唯一、试磨关系、冻结↔预警状态、召回快照/复测齐全、冻结 targetKey 唯一）。

### 身份与故障注入（用于验证）

写接口用请求头 `x-user-id` 标识操作人，缺失或伪造返回 401。内置账号：

- `u01` 沈研工（检验员）　`u02` 林质管（质量主管）　`u03` 周复核（复核员）

请求头 `x-simulate: write-fail` 可令该次写入在临时文件写完、rename 之前失败，用于验证回滚。

### 验证

```bash
npm test
```

`test/verify.mjs` 会拉起真实 `server.js` 子进程（独立临时库，从真实旧格式数据迁移），实测：留样/预警的并发唯一、越权（401/403）、状态机非法跳转、**待复核未复核直接关闭被明确拒绝且状态/审计/冻结不变**、**提交人放行/召回/复核全程回避（自行复核 403 且状态/时间线/审计/冻结不变）**、放行与召回两条路径都必须由他人先复核、写失败回滚无部分落盘、`SIGKILL` 硬重启后关系与版本一致，共 77 项断言。
